# CampusSphere Project Rules

These rules apply to every AI assistant working on this project.

## General Rules

- Never change the tech stack.
- Never replace Django with another backend.
- Never replace React with another frontend framework.
- Never generate fake data unless explicitly requested.
- Never create fake testimonials.
- Never create fake statistics.
- Never create placeholder universities.
- Never invent features not present in the Product Bible.
- Never remove existing features without approval.

## UI Rules

- Mobile-first responsive design.
- Modern, premium UI.
- Consistent spacing.
- Accessible components.
- Dark mode support.
- Smooth animations only where meaningful.
- Avoid clutter.

## Code Rules

- Write production-quality code.
- Use TypeScript everywhere in the frontend.
- Follow Django best practices.
- No duplicated code.
- Reusable components only.
- Modular architecture.

## Git Rules

- One feature per branch.
- Small commits.
- Descriptive commit messages.
- No direct commits to main.

## Performance Rules

- Lazy load pages.
- Optimize images.
- Avoid unnecessary re-renders.
- Minimize API requests.

## Security Rules

- Validate all input.
- Protect authenticated routes.
- Never expose secrets.
- Hash passwords.
- Follow OWASP best practices.

## Product Rules

Every feature must support at least one of these goals:

- Learn
- Collaborate
- Compete
- Grow
- Connect

If a feature does not support these goals, it should not be added.
